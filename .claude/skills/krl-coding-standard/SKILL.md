# KRL コーディング作法【構築中】

> **この規約は構築中です。** 実機に触れながら洗練させる前提で作っています。
> 条項には `確定` / `暫定` / `保留` の状態が付いています。**`暫定` に出会ったら、
> 従ったうえで「暫定である」と明示してください。** 黙って確定扱いしないこと。

## 0. 大前提

**過去コードの書き方は根拠になりません。** ISC / W3D / 愛知産業のコードには、
プログラマ不在のまま積み上がった問題が多数あります。UEC のコードは比較的
まともですが、それでも規範ではありません。

根拠として使えるのは3つだけです。出典を必ず区別してください。

| 出典区分 | 意味 |
|---|---|
| **一次資料** | KUKA 公式マニュアル（KSS 8.7 SI / System Variables / KRL Reference） |
| **稼働実績** | 実機で動いたことが確認されているコード |
| **二次資料** | 非公式の解説。仮説として扱う |

一次資料と稼働実績が矛盾したら、**どちらも記録して実機で決着**させます。
片方だけで断定しないこと。（→ `references/90-facts.md`）

## 1. 対象

- KUKA KR 50 R2500 + 外部キネマティクス KP1-V1000（Base[17]）
- KSS 8.x / KR C4
- WAAM（アーク溶接による金属積層造形）
- モジュール例: `WBead`（ウィービングビード）、`SBead`（ストリンガービード、予定）

## 2. 使い方

新規プログラムを書くとき、既存を直すとき、レビューするときの手順です。

1. **`references/00-principles.md`** を読む。判断に迷ったらここに戻る
2. 書く内容に応じて該当条項を読む
   - 命名 → `references/01-naming.md`（N1〜N10）
   - 変数の置き場所・引数 → `references/02-variables.md`（S1〜S13）
   - 動作命令・座標系・S/T → `references/03-motion.md`（M1〜M9, C1〜C8）
   - 実機での検証の進め方 → `references/04-verification.md`（T1〜T8）
   - ファイル命名・版管理・造形の記録 → `references/05-versioning.md`（V1〜V8）
3. 書き始め方（雛形は持たない。2026-09-29 に廃止）
   - **同じプログラムの新しい版** → 前の版をコピーして始める（手順は `05-versioning.md` V1「新しい版の作り方」）
   - **別の種類のプログラム** → 丸ごとはコピーしない。作法に沿って新しく書き、実績のある**部分**
     （座標系の設定、速度の設定、ARC ON / OFF など）だけを、複製元をコメントに書いて写す（P2）
   - 実績のあるプログラムは、実機の写し（Library の `ref/KUKA_3261646/snapshot/`）で見られる。
     各プログラムの正本は、その版を作ったプロジェクトにある
4. 書き終えたら `references/91-open.md` のチェックリストで自己点検
5. 未検証の前提を使ったら `;@ASSUME` を付ける（N10）

**実機を動かすときは必ず `04-verification.md` を読むこと。**
「モード T1 で動いた」は AUTO の検証にならない。ここを飛ばした結果、
AUTO で軸速度超過により停止した実例がある。

既存コードをレビューするときは、先に `references/91-open.md` の
「アンチパターン集」を読んでください。同じ失敗が繰り返し出ます。

## 4. 編集手順

この規約は育てる前提です。変更するときは：

1. **条項番号を変えない。** 廃止するときは番号を残して「廃止」と書く
2. **根拠を必ず書く。** 「〜だから」が無い条項は後で誰も守れない
3. **状態を更新する。** `暫定` → `確定` に上げるときは、何で確定したかを
   `references/90-facts.md` に追記する
4. **実機で分かったことは `90-facts.md` へ、分からなかったことは
   `91-open.md` へ。** 両方に書かない
5. 撤回した条項は消さずに `91-open.md` の「撤回した判断」に移す。
   同じ検討を繰り返さないため

## 5. よくある誤り（この規約を使う側の）

- **一次資料に書いていない = 使えない、と断定する。**
  マニュアルは網羅的とは限りません。稼働実績と矛盾したら保留にすること
- **既存コードの書き方に合わせようとする。** 合わせる必要はありません
- **`暫定` を確定として扱う。** 必ず「これは暫定」と添えてください
- **頼まれていないレビューを始める。** コードを共有されただけなら読むだけ
